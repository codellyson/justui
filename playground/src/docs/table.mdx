# Table

Renders rows and nothing else — columns are
[TanStack Table](https://tanstack.com/table) v8 `ColumnDef`s, so custom cells,
column sizes and grouped headers all work unchanged. Paging, sorting and
filtering stay yours: slice the `data` you pass in and compose
[Pagination](#pagination) beside it.

```jsx live noInline
const rows = [
  { name: 'api-gateway', region: 'us-east-1', status: 'live', requests: 128400 },
  { name: 'billing-worker', region: 'eu-west-2', status: 'live', requests: 9120 },
  { name: 'image-resizer', region: 'us-east-1', status: 'draft', requests: 0 },
  { name: 'search-index', region: 'ap-south-1', status: 'paused', requests: 431 },
];

const columns = [
  { accessorKey: 'name', header: 'Service', cell: (c) => <span className="font-medium">{c.getValue()}</span> },
  { accessorKey: 'region', header: 'Region' },
  {
    accessorKey: 'status',
    header: 'Status',
    cell: (c) => (
      <Badge variant="light" color={{ live: 'green', draft: 'gray', paused: 'yellow' }[c.getValue()]}>
        {c.getValue()}
      </Badge>
    ),
  },
  {
    accessorKey: 'requests',
    header: 'Requests',
    cell: (c) => <span className="font-mono">{c.getValue().toLocaleString()}</span>,
  },
];

render(<Table columns={columns} data={rows} />);
```

`header` and `cell` are TanStack render slots, so a cell can return any node — a
`Badge`, a `Button`, a nested component. `columns` is data like `Select`'s
options, not children.

## Paging a table

There's no `pageSize` prop. The page is a slice of your own data, which is the
same shape whether the rows came from memory or from a request.

```jsx live noInline
const ALL = Array.from({ length: 47 }, (_, i) => ({
  build: `#${2100 + i}`,
  branch: i % 3 === 0 ? 'main' : `feat/queue-${i}`,
  duration: `${(1 + (i % 7) * 0.4).toFixed(1)}s`,
}));

const columns = [
  { accessorKey: 'build', header: 'Build' },
  { accessorKey: 'branch', header: 'Branch' },
  { accessorKey: 'duration', header: 'Duration' },
];

function Demo() {
  const [page, setPage] = useState(1);
  const perPage = 8;
  const total = Math.ceil(ALL.length / perPage);
  const start = (page - 1) * perPage;
  const rows = ALL.slice(start, start + perPage);

  return (
    <div className="space-y-4">
      <Table columns={columns} data={rows} />
      <div className="flex flex-wrap items-center justify-between gap-4">
        <p className="text-sm text-muted">
          Showing{' '}
          <span className="font-medium text-primary">
            {start + 1}–{Math.min(start + perPage, ALL.length)}
          </span>{' '}
          of {ALL.length}
        </p>
        <Pagination page={page} total={total} onChange={setPage} />
      </div>
    </div>
  );
}

render(<Demo />);
```

Server-side paging is the same code with a request in place of `slice` — `page`
goes out, rows come back, `total` comes from the response. Nothing about the
table changes.

## Borders

Rows are separated by default and nothing else. Pass `bordered` to frame the
table; column dividers stay off unless you ask for them.

```jsx live noInline
const columns = [
  { accessorKey: 'metric', header: 'Metric' },
  { accessorKey: 'p50', header: 'p50' },
  { accessorKey: 'p99', header: 'p99' },
];

const data = [
  { metric: 'render', p50: '12ms', p99: '48ms' },
  { metric: 'query', p50: '3ms', p99: '210ms' },
  { metric: 'upload', p50: '90ms', p99: '1.4s' },
];

render(
  <div className="space-y-8">
    <Table columns={columns} data={data} />
    <Table columns={columns} data={data} bordered={{}} />
    <Table columns={columns} data={data} bordered={{ column: true }} />
  </div>
);
```

Top to bottom: no frame, `bordered={{}}`, then `bordered={{ column: true }}`.
Providing `bordered` at all is what draws the outer frame — `column` is the
separate opt-in for the vertical rules, since they add a lot of ink for data that
already lines up.

## Loading and empty

```jsx live noInline
const columns = [
  { accessorKey: 'name', header: 'Name' },
  { accessorKey: 'role', header: 'Role' },
  { accessorKey: 'seat', header: 'Seat' },
];

render(
  <div className="space-y-8">
    <Table columns={columns} data={[]} isLoading loadingRows={3} />
    <Table columns={columns} data={[]} emptyMessage="No teammates yet — invite someone." />
  </div>
);
```

`isLoading` renders `loadingRows` skeleton rows against the real column count, so
the layout doesn't jump when the data lands. An empty result gets `emptyMessage`
rather than a bare `tbody`.

## Row clicks and a hidden header

```jsx live noInline
const columns = [
  { accessorKey: 'key', header: 'Key' },
  { accessorKey: 'value', header: 'Value' },
];

const data = [
  { key: 'DATABASE_URL', value: 'postgres://…' },
  { key: 'REDIS_URL', value: 'redis://…' },
];

function Demo() {
  const [picked, setPicked] = useState(null);
  return (
    <div className="space-y-3">
      <Table columns={columns} data={data} hideHeader onRowClick={(row) => setPicked(row.key)} />

```

`onRowClick` receives the original row object, not the TanStack wrapper. Rows
take a pointer cursor and a hover only when it's set.

## Sorting

`sortable` turns every eligible header into a button that cycles through three
states, with `aria-sort` kept in step.

```jsx live noInline
const data = [
  { service: 'api-gateway', region: 'us-east-1', p99: 48, cost: 412.1 },
  { service: 'billing-worker', region: 'eu-west-2', p99: 210, cost: 38.44 },
  { service: 'image-resizer', region: 'us-east-1', p99: 1400, cost: 96.2 },
  { service: 'search-index', region: 'ap-south-1', p99: 12, cost: 7.05 },
];

const columns = [
  { accessorKey: 'service', header: 'Service' },
  { accessorKey: 'region', header: 'Region', enableSorting: false },
  {
    accessorKey: 'p99',
    header: 'p99',
    cell: (c) => <span className="font-mono">{c.getValue()}ms</span>,
  },
  {
    accessorKey: 'cost',
    header: 'Cost',
    cell: (c) => <span className="font-mono">${c.getValue().toFixed(2)}</span>,
  },
];

render(<Table columns={columns} data={data} sortable defaultSorting={[{ id: 'p99', desc: true }]} />);
```

Region opts out with `enableSorting: false` and stays a plain header — no button,
no `aria-sort`. `defaultSorting` sets the initial order; the table owns the state
from there.

Which direction a first click picks depends on the data, not on a fixed cycle:
text columns start ascending, numbers start **descending** so the largest lands on
top. TanStack infers this from the first row's value, and `sortDescFirst` on the
column overrides it. The third click clears the sort and the source order returns.

Comparison is type-aware too — `p99` orders 12 → 48 → 210 → 1400, not
lexically.

### Server-side sorting

Pass `sorting` and `onSortingChange` to own the state, and `manualSorting` so the
rows you supply are rendered in the order you supplied them.

```jsx live noInline
const ROWS = [
  { service: 'api-gateway', p99: 48 },
  { service: 'billing-worker', p99: 210 },
  { service: 'image-resizer', p99: 1400 },
  { service: 'search-index', p99: 12 },
];

const columns = [
  { accessorKey: 'service', header: 'Service' },
  { accessorKey: 'p99', header: 'p99', cell: (c) => <span className="font-mono">{c.getValue()}ms</span> },
];

function Demo() {
  const [sorting, setSorting] = useState([{ id: 'service', desc: false }]);

  // Stands in for a request keyed on the sort.
  const rows = [...ROWS].sort((a, b) => {
    const { id, desc } = sorting[0] ?? {};
    if (!id) return 0;
    const dir = desc ? -1 : 1;
    return a[id] > b[id] ? dir : a[id] < b[id] ? -dir : 0;
  });

  return (
    <div className="space-y-3">
      <Table
        columns={columns}
        data={rows}
        sortable
        manualSorting
        sorting={sorting}
        onSortingChange={setSorting}
      />
      <p className="text-xs text-muted">
        sent to the server: <code>{JSON.stringify(sorting)}</code>
      </p>
    </div>
  );
}

render(<Demo />);
```

`onSortingChange` receives the resolved `SortingState` — an array, not an updater
function — so it drops straight into a `useState` setter or a request.

### On the parts

`Table.Head` carries the affordance, so an authored table sorts the same way:
`sortDirection` is `"asc"`, `"desc"`, or `false` for sortable-but-unsorted, and
omitting it leaves a plain header. Wire it to whatever state you like.

```jsx live noInline
function Demo() {
  const [sort, setSort] = useState({ key: 'name', desc: false });
  const rows = [
    { name: 'nord', downloads: 1204 },
    { name: 'espresso', downloads: 8890 },
    { name: 'gruvbox', downloads: 430 },
  ];
  const sorted = [...rows].sort((a, b) => {
    const dir = sort.desc ? -1 : 1;
    return a[sort.key] > b[sort.key] ? dir : a[sort.key] < b[sort.key] ? -dir : 0;
  });
  const head = (key, label) => (
    <Table.Head
      className={key === 'downloads' ? 'text-right' : undefined}
      sortDirection={sort.key === key ? (sort.desc ? 'desc' : 'asc') : false}
      onSort={() => setSort((s) => ({ key, desc: s.key === key ? !s.desc : false }))}
    >
      {label}
    </Table.Head>
  );

  return (
    <Table.Root bordered={{}}>
      <Table.Header>
        <Table.Row>
          {head('name', 'Theme')}
          {head('downloads', 'Downloads')}
        </Table.Row>
      </Table.Header>
      <Table.Body>
        {sorted.map((row) => (
          <Table.Row key={row.name}>
            <Table.Cell className="font-medium">{row.name}</Table.Cell>
            <Table.Cell className="text-right font-mono">{row.downloads.toLocaleString()}</Table.Cell>
          </Table.Row>
        ))}
      </Table.Body>
    </Table.Root>
  );
}

render(<Demo />);
```

## Row selection

`enableRowSelection` adds a leading checkbox column with a select-all in the
header, which goes indeterminate on a partial selection.

```jsx live noInline
const ROWS = [
  { id: 'srv_1', service: 'api-gateway', p99: 48 },
  { id: 'srv_2', service: 'billing-worker', p99: 210 },
  { id: 'srv_3', service: 'image-resizer', p99: 1400 },
  { id: 'srv_4', service: 'search-index', p99: 12 },
];

const columns = [
  { accessorKey: 'service', header: 'Service' },
  { accessorKey: 'p99', header: 'p99', cell: (c) => <span className="font-mono">{c.getValue()}ms</span> },
];

function Demo() {
  const [selection, setSelection] = useState({ srv_2: true });
  const picked = Object.keys(selection).filter((key) => selection[key]);

  return (
    <div className="space-y-3">
      <Table
        columns={columns}
        data={ROWS}
        sortable
        enableRowSelection
        getRowId={(row) => row.id}
        rowSelection={selection}
        onRowSelectionChange={setSelection}
        selectionLabel={(row) => `Select ${row.service}`}
      />
      <div className="flex items-center gap-3">
        <p className="text-xs text-muted">
          selected: <code>{picked.length ? picked.join(', ') : '(none)'}</code>
        </p>
        {picked.length > 0 && (
          <Button size="xs" variant="outline" onClick={() => setSelection({})}>
            Clear
          </Button>
        )}
      </div>
    </div>
  );
}

render(<Demo />);
```

**Pass `getRowId`.** Without it TanStack keys selection by row *index*, so sorting
the table moves your selection to whatever row now sits in that position. Try
sorting by p99 above — the selection stays on `billing-worker`, because the key is
its `id`.

`selectionLabel` names each checkbox for screen readers; without it they read
"Select row 1". The header box reports `indeterminate` when only some rows are
selected, and clicking a checkbox never triggers `onRowClick`.

### Uncontrolled, and rows that can't be selected

Omit `rowSelection` to let the table own the state, and pass a predicate to
`enableRowSelection` to exclude rows.

```jsx live noInline
const ROWS = [
  { id: 'a', name: 'draft-post', status: 'draft' },
  { id: 'b', name: 'published-post', status: 'published' },
  { id: 'c', name: 'archived-post', status: 'archived' },
  { id: 'd', name: 'another-draft', status: 'draft' },
];

const columns = [
  { accessorKey: 'name', header: 'Name' },
  {
    accessorKey: 'status',
    header: 'Status',
    cell: (c) => (
      <Badge variant="light" color={{ draft: 'gray', published: 'green', archived: 'yellow' }[c.getValue()]}>
        {c.getValue()}
      </Badge>
    ),
  },
];

function Demo() {
  const [opened, setOpened] = useState(null);
  return (
    <div className="space-y-3">
      <Table
        columns={columns}
        data={ROWS}
        getRowId={(row) => row.id}
        enableRowSelection={(row) => row.original.status !== 'archived'}
        defaultRowSelection={{ a: true }}
        onRowClick={(row) => setOpened(row.name)}
        bordered={{}}
      />
      <p className="text-xs text-muted">
        row click: <code>{opened ?? '(none)'}</code>
      </p>
    </div>
  );
}

render(<Demo />);
```

The archived row's checkbox is disabled, and select-all skips it — so the header
box reads fully checked once the three selectable rows are on.

This one also has `onRowClick`. Clicking a checkbox toggles selection **without**
firing it, so the two interactions don't fight; clicking anywhere else in the row
does.

## Writing the markup yourself

`columns` and `data` suit real tabular data. For a short static table, a totals
row, or a group heading spanning the width, the parts are the same styled
elements `Table` is built from — so an authored table matches a data-driven one
exactly.

```jsx live
<Table.Root bordered={{}}>
  <Table.Caption>Spend by region, last 30 days</Table.Caption>
  <Table.Header>
    <Table.Row>
      <Table.Head>Region</Table.Head>
      <Table.Head className="text-right">Requests</Table.Head>
      <Table.Head className="text-right">Cost</Table.Head>
    </Table.Row>
  </Table.Header>
  <Table.Body>
    <Table.Row>
      <Table.Cell className="font-medium">us-east-1</Table.Cell>
      <Table.Cell className="text-right font-mono">128,400</Table.Cell>
      <Table.Cell className="text-right font-mono">$412.10</Table.Cell>
    </Table.Row>
    <Table.Row>
      <Table.Cell className="font-medium">eu-west-2</Table.Cell>
      <Table.Cell className="text-right font-mono">9,120</Table.Cell>
      <Table.Cell className="text-right font-mono">$38.44</Table.Cell>
    </Table.Row>
  </Table.Body>
  <Table.Footer>
    <Table.Row>
      <Table.Cell>Total</Table.Cell>
      <Table.Cell className="text-right font-mono">137,520</Table.Cell>
      <Table.Cell className="text-right font-mono">$450.54</Table.Cell>
    </Table.Row>
  </Table.Footer>
</Table.Root>
```

`Table` renders data; `Table.Root` and friends are the primitives underneath.
`bordered` goes on `Root` and reaches the rows through context, so column
dividers work the same in both forms.

### Rows that aren't data rows

A `colSpan` group heading, a subtotal, an expanded detail row — none of these fit
a `ColumnDef`, and all of them are ordinary markup here.

```jsx live noInline
function Demo() {
  const [open, setOpen] = useState('api-gateway');
  const groups = [
    {
      region: 'us-east-1',
      services: [
        { name: 'api-gateway', p99: '48ms', detail: 'Cached at the edge for 60s.' },
        { name: 'image-resizer', p99: '1.4s', detail: 'Cold starts dominate the tail.' },
      ],
    },
    {
      region: 'eu-west-2',
      services: [{ name: 'billing-worker', p99: '210ms', detail: 'Waits on the ledger write.' }],
    },
  ];

  return (
    <Table.Root bordered={{ column: true }}>
      <Table.Header>
        <Table.Row>
          <Table.Head>Service</Table.Head>
          <Table.Head className="text-right">p99</Table.Head>
        </Table.Row>
      </Table.Header>
      <Table.Body>
        {groups.map((group) => (
          <React.Fragment key={group.region}>
            <Table.Row className="bg-bg-secondary">
              <Table.Cell colSpan={2} className="py-1.5 text-xs uppercase tracking-wider text-muted">
                {group.region}
              </Table.Cell>
            </Table.Row>
            {group.services.map((service) => (
              <React.Fragment key={service.name}>
                <Table.Row
                  onClick={() => setOpen(open === service.name ? null : service.name)}
                  className="cursor-pointer hover:bg-bg-secondary"
                >
                  <Table.Cell className="font-medium">{service.name}</Table.Cell>
                  <Table.Cell className="text-right font-mono">{service.p99}</Table.Cell>
                </Table.Row>
                {open === service.name && (
                  <Table.Row>
                    <Table.Cell colSpan={2} className="bg-bg-secondary text-xs text-secondary">
                      {service.detail}
                    </Table.Cell>
                  </Table.Row>
                )}
              </React.Fragment>
            ))}
          </React.Fragment>
        ))}
      </Table.Body>
    </Table.Root>
  );
}

render(<Demo />);
```

Click a service to expand it. Every part forwards its native attributes, so
`colSpan`, `scope`, `onClick` and `style` all work as they would on the raw
element.

## Large tables

`Table` renders every row it is given, and the cost is linear in row count. Some
rough figures from this gallery's dev build — a production bundle is faster, but
the shape holds:

| Rows | One selection toggle | Sort |
|---|---|---|
| 50 | ~150ms | ~175ms |
| 1000 | ~1450ms | ~1900ms |

About 3ms a row. That cost is plain React reconciliation, not any one feature —
sorting 1000 rows costs the same whether row selection is on or off — so the fix
is always to render fewer rows, never to shave the per-row work.

**Paginate first.** A 25–50 row page keeps every interaction comfortable, and
[Pagination](#pagination) composes with `Table` without either knowing about the
other. This covers almost every table in an application.

**Virtualize when the list genuinely can't be paged** — an audit log you scroll,
a picker over thousands of rows. Use
[@tanstack/react-virtual](https://tanstack.com/virtual); it isn't a dependency of
this package, so install it yourself.

Note that virtualizing means driving the markup directly, since the data-driven
`Table` has no seam for it: keep your own TanStack instance and render its rows
through the parts shown above, which is exactly what they're for. Roughly:

```jsx
const rows = table.getRowModel().rows;
const virtualizer = useVirtualizer({
  count: rows.length,
  getScrollElement: () => scrollRef.current,
  estimateSize: () => 41,
  overscan: 8,
});
const items = virtualizer.getVirtualItems();

<div ref={scrollRef} className="h-96 overflow-auto">
  <Table.Root>
    <Table.Header>{/* … */}</Table.Header>
    <Table.Body>
      {items[0]?.start > 0 && (
        <Table.Row><Table.Cell style={{ height: items[0].start, padding: 0 }} /></Table.Row>
      )}
      {items.map((item) => {
        const row = rows[item.index];
        return (
          <Table.Row key={row.id} data-index={item.index}>
            {row.getVisibleCells().map((cell) => (
              <Table.Cell key={cell.id}>
                {flexRender(cell.column.columnDef.cell, cell.getContext())}
              </Table.Cell>
            ))}
          </Table.Row>
        );
      })}
    </Table.Body>
  </Table.Root>
</div>
```

A sketch, not a copy-paste drop-in — the spacer rows above and below the window
are what keep the scrollbar honest, and a `<table>` needs them as rows rather than
the absolute positioning you would use on a list of divs. Fixed row heights make
this far easier than measured ones.

### Parts

`Table.Root` · `Table.Caption` · `Table.Header` · `Table.Body` · `Table.Footer` ·
`Table.Row` · `Table.Head` · `Table.Cell`

`Head` also takes `sortDirection` and `onSort`. Each part otherwise takes its
element's native props plus `className`. `Root` also takes
`bordered` and `wrapperClassName`, since `className` there lands on the `<table>`
while the border and scrolling live on the wrapper around it. All are exported
flat too (`TableRoot`, `TableCell`, …).

`ColumnDef` is re-exported, so the common case needs no direct
`@tanstack/react-table` import. Keep `columns` and `data` referentially stable —
define columns at module scope, or memoise them — so the table isn't rebuilt on
every render.

Wide tables scroll horizontally inside their own container rather than stacking
each row into an unlabeled column list on narrow screens.
