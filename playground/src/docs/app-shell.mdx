# AppShell

The frame an application sits in — header, footer, left navbar, right aside, and a
main area offset from all of them. Sizes go on the root as config and reach the
parts through CSS variables, so nothing is repeated.

Every region is optional. Leave one out and no space is reserved for it.

Press the burger to collapse the navbar to a rail: `collapsedWidth` narrows it and
every `NavLink` drops to its icon with the label moving into a tooltip. Main's left
offset follows, because the width is one variable.

## Navbar sections

`AppShell.Section` divides the navbar. Exactly one section takes `grow` — it
absorbs the leftover height and scrolls, which pins whatever sits above and below
it. That's how a long link list keeps the account row visible at the bottom.

```jsx live noInline
function Demo() {
  return (
    <div
      className="relative h-[300px] overflow-hidden rounded-lg border border-border"
      style={{ transform: 'translate(0)' }}
    >
      <AppShell navbar={{ width: 200, breakpoint: 'sm' }} padding="sm" className="min-h-full">
        <AppShell.Navbar className="p-2">
          <AppShell.Section className="pb-2 text-xs font-medium uppercase tracking-wider text-muted">
            Pinned top
          </AppShell.Section>
          <AppShell.Section grow className="flex flex-col gap-1">
            {Array.from({ length: 14 }, (_, i) => (
              <NavLink key={i} label={`Project ${i + 1}`} active={i === 1} />
            ))}
          </AppShell.Section>
          <AppShell.Section className="-mx-2 mt-2 border-t border-border px-2 pt-2 text-xs text-muted">
            Pinned bottom
          </AppShell.Section>
        </AppShell.Navbar>
        <AppShell.Main>
          <p className="text-sm text-secondary">Scroll the navbar — the ends stay put.</p>
        </AppShell.Main>
      </AppShell>
    </div>
  );
}

render(<Demo />);
```

## Layouts

`layout="alt"` runs the navbar the full height of the shell and starts the header
beside it. `default` keeps the header across the top.

```jsx live noInline
const shell = (layout) => (
  <div
    className="relative h-52 overflow-hidden rounded-lg border border-border"
    style={{ transform: 'translate(0)' }}
  >
    <AppShell
      layout={layout}
      header={{ height: 40 }}
      navbar={{ width: 96, breakpoint: 'sm' }}
      padding="sm"
      className="min-h-full"
    >
      <AppShell.Header className="px-3 text-xs font-semibold">header</AppShell.Header>
      <AppShell.Navbar className="p-2 text-xs text-muted">navbar</AppShell.Navbar>
      <AppShell.Main>
        <p className="font-mono text-xs text-secondary">layout="{layout}"</p>
      </AppShell.Main>
    </AppShell>
  </div>
);

render(
  <div className="grid gap-6 md:grid-cols-2">
    {shell('default')}
    {shell('alt')}
  </div>
);
```

## Collapsing on small screens

Navbar and aside each hide below their own breakpoint — `md` and `lg` by default.
Below it, `opened` brings the region in over the content with an overlay that
dismisses on click or Escape.

The demo uses `breakpoint="xl"` for both, so narrow this window under 1280px to
see them collapse. Above that they're pinned and `opened` has nothing to do.

```jsx live noInline
function Demo() {
  const [nav, setNav] = useState(false);
  const [aside, setAside] = useState(false);
  return (
    <div
      className="relative h-[300px] overflow-hidden rounded-lg border border-border"
      style={{ transform: 'translate(0)' }}
    >
      <AppShell
        header={{ height: 48 }}
        navbar={{ width: 180, breakpoint: 'xl', opened: nav, onClose: () => setNav(false) }}
        aside={{ width: 180, breakpoint: 'xl', opened: aside, onClose: () => setAside(false) }}
        className="min-h-full"
      >
        <AppShell.Header className="gap-2 px-2">
          <Button size="xs" variant="ghost" onClick={() => setNav((o) => !o)}>Nav</Button>
          <Button size="xs" variant="ghost" className="ml-auto" onClick={() => setAside((o) => !o)}>
            Aside
          </Button>
        </AppShell.Header>
        <AppShell.Navbar className="p-2">
          <NavLink label="Overview" onClick={() => setNav(false)} />
          <NavLink label="Logs" onClick={() => setNav(false)} />
        </AppShell.Navbar>
        <AppShell.Aside className="p-3 text-sm text-secondary">Aside panel</AppShell.Aside>
        <AppShell.Main>
          <p className="text-sm text-secondary">
            nav: <code>{String(nav)}</code> · aside: <code>{String(aside)}</code>
          </p>
        </AppShell.Main>
      </AppShell>
    </div>
  );
}

render(<Demo />);
```

## Props

### AppShell

| Prop | Type | Default |
|---|---|---|
| `header` | `{ height }` | — |
| `footer` | `{ height }` | — |
| `navbar` | `{ width, collapsedWidth?, collapsed?, breakpoint?, opened?, onClose? }` | — |
| `aside` | `{ width, breakpoint?, opened?, onClose? }` | — |
| `layout` | `default` `alt` | `default` |
| `padding` | `none` `xs` `sm` `md` `lg` `xl` | `md` |

Sizes take a number (px) or any CSS length. `navbar.breakpoint` defaults to `md`,
`aside.breakpoint` to `lg`. `collapsed` is inert unless `collapsedWidth` is set.

### Parts

`AppShell.Header` · `.Footer` · `.Navbar` · `.Aside` · `.Section` · `.Main` — each
takes its element's native props. `Section` takes `grow`. A part used outside an
`AppShell` throws rather than rendering something subtly wrong.

`useAppShellNavbar()` returns `{ collapsed, opened }`, which is how `NavLink`
knows to go icon-only. Use it for your own navbar content.

The regions are `fixed`, which is what keeps them still while main scrolls. To
contain the shell in a box rather than the viewport — as this page does — give the
wrapper a `transform`, making it the containing block for fixed descendants.
